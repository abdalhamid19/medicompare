## المكونات الأساسية

### 1. normalizer.py - التطبيع والتحليل

**الثوابت الرئيسية:**
- `FORM_WORDS`: أشكال الأدوية (TAB, CAP, SYRUP, etc)
- `FORM_PREFIXES`: بادئات الأشكال (CREAM, GEL, INJECTION, etc)
- `NOISE_WORDS`: كلمات تُزال (BLUE, RED, WHITE)
- `CRITICAL_MODIFIERS`: كلمات تُحفظ (PLUS, EXTRA, IMP, IMPORTED)

**الدوال الرئيسية:**

```python
normalize(name: str) -> str
```
تنظيف النص:
1. تحويل لأحرف كبيرة
2. إزالة بادئات الضوضاء
3. معالجة التدوين العشري الأوروبي
4. إزالة النقاط (مع الحفاظ على الكسور العشرية)
5. توحيد المسافات

```python
parse_drug(name: str) -> DrugComponents
```
استخراج المكونات:

| المكون | النوع | مثال |
|---|---|---|
| brand | str | PANADOL |
| dosage_nums | tuple | ('500',) |
| dosage_units | tuple | ('MG',) |
| qty | str | 30 |
| volume | str | 120 |
| weight | str | 30 |
| form | str | TAB |
| normalized | str | PANADOL 500 MG 30 TAB |

### 2. indexer.py - الفهرسة والبحث

**البناء:**
- يقرأ ملف المنتجات ويبني فهرساً مقلوباً
- يخزن نسخة مُحللة من كل منتج (parsed_cache)

**الخوارزميات:**

```
lookup_by_brand(drug_components)
├─ استخرج العلامة التجارية
├─ ابحث في الفهرس بالبادئات (من طويل لقصير)
├─ صفّي النتائج بـ components_match
└─ أرجع قائمة المرشحين الصالحين
```

```
fuzzy_match(query, top_k)
├─ جرب token_set_ratio
├─ جرب token_sort_ratio
├─ جرب partial_token_sort_ratio
└─ أرجع أفضل top_k النتائج
```

---

### 3. verifier.py - التحقق بالـ AI

**الميزات:**
- طلبات غير متزامنة (async)
- تحديد معدل (Semaphore) لتجنب الإرهاق
- معالجة الأخطاء والـ timeouts
- دعم الدفعات (batching)

**الـ System Prompt:**
يحدد 7 قواعد صارمة للتحقق:
1. العلامة التجارية يجب أن تكون مطابقة تماماً
2. أرقام الجرعة يجب أن تكون مطابقة
3. الكمية يجب أن تكون مطابقة
4. الحجم يجب أن يكون مطابقاً
5. الشكل الدوائي يجب أن يكون مطابقاً
6. لا تطابق بين علامات تجارية مختلفة
7. PLUS/EXTRA في واحد دون الآخر = عدم تطابق

---

### 4. pipeline.py - منسق الـ Pipeline

**4 مراحل رئيسية:**

```
المرحلة 1: المطابقة الخوارزمية
├─ لكل دواء: DrugIndex.best_match()
├─ إذا وجد: verified = "algo_match"
└─ إذا لم يجد: verified = "no_match"

المرحلة 2: التحقق بالـ AI
├─ لكل تطابق بنسبة < 90%: AIVerifier.verify_one()
├─ إذا صحيح: verified = "ai_confirmed"
├─ إذا خاطئ: ابحث عن بديل أفضل
│   ├─ وجدت: verified = "ai_corrected"
│   └─ لم تجد: verified = "ai_rejected"

المرحلة 3: بحث الـ AI عن مطابقات جديدة
├─ لكل صنف غير مطابق: fuzzy + components_match
├─ اطلب من الـ AI اختيار الأفضل
└─ إذا ثقة >= 0.7: verified = "ai_found"

المرحلة 4: التنظيف الخوارزمي النهائي
├─ أعد تحليل كل تطابق
├─ تحقق من المكونات
└─ احذف التطابقات الخاطئة
```

## تدفق البيانات (Data Flow)

```
Drug: "PANADOL PLUS 500 MG 30 TABLET"
  │
  ├─> NORMALIZER
  │   └─> "PANADOL PLUS 500 MG 30 TAB"
  │
  ├─> PARSER
  │   ├─ brand: "PANADOL"
  │   ├─ dosage_nums: ('500',)
  │   ├─ dosage_units: ('MG',)
  │   ├─ qty: "30"
  │   ├─ form: "TAB"
  │   └─ critical_mod: "PLUS"
  │
  ├─> INDEXER (Brand Search)
  │   ├─ بحث في الفهرس بـ: PAN, PANA, PANAD, PANADO, PANADOL
  │   ├─ وجد: PANADOL 500 MG 30 TAB (في المخزن)
  │   └─ تقييم: 95% (>= 80%) ✅
  │
  └─> RESULT: "PANADOL 500 MG 30 TAB" (match_score=95)
```

## الأداء

| العملية | التعقيد الزمني | الوقت التقريبي |
|---|---|---|
| تطبيع اسم واحد | O(n) | <1ms |
| بحث بالعلامة التجارية | O(1) | <0.1ms |
| بحث Fuzzy | O(n) | 50-200ms |
| تحقق AI واحد | O(1) | 1-3 ثانية |
| تحقق AI دفعة (20) | O(1) | 3-5 ثواني (متوازي) |

**التحسينات:**
- Inverted Index: تقليل البحث من O(n) إلى O(1)
- Parsed Cache: عدم إعادة تحليل نفس المنتج
- Semaphore: تحديد الطلبات المتزامنة (max 5)
- Batching: معالجة 20 تطابق معاً

## الأخطاء الشائعة والحلول

### 1. الـ Brand Index يفشل
→ تنتقل تلقائياً إلى Fuzzy Matching

### 2. التطابق بنسبة منخفضة (<80%)
→ يتم إرسال للتحقق بالـ AI

### 3. الـ AI يؤكد تطابق خاطئ
→ يتم التنظيف الخوارزمي في المرحلة 4

### 4. API timeout
→ معالجة خاصة في AIVerifier مع إعادة محاولة
